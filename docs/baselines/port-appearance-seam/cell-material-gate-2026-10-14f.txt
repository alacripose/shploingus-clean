--- what those numbers say, one clause at a time

* **the frame's digest moves with the cell** — `7816bf6a…` -> `9cb6c6ca…`. The frame before the write is the
  frame this tree drew before this pass (the drawn reading's own digest on the unchanged world, §11's own
  `7816bf6a…`), so the moved digest is the moved cell and nothing else.
* **the same number of pixels is drawn** — `147808 -> 147808`. A material is not a shape: the write changes
  what a rectangle is *made of*, not which rectangles exist, so the picture's coverage is the invariant and its
  colour is the variable. This is the flicker's own subject: a viewer sees a *colour* change on a *picture that
  did not move*, which is exactly what the parent's per-column path could not keep still.
* **the mesh's digest moves with it** — `24d61db2…` -> `13733560…`. The rectangle that covers the cell carries
  its material (`Quad::material`), so a cell's material reaches the geometry's own bytes: the mesh is not a
  second, stale copy of the same fact.
* **the world's own identity moves with it** — `7675fd92…` -> `940ff716…`. The store's digest is over its
  cells, material included, so a frame's mesh state is a *state* and not a camera.

--- the guards that hold it, and that the two worlds are two

The subject asserts, in order: the two worlds are the same world before the write (`digest` equal); the write
touched exactly one cell (the store's `material_at` at that cell answers the new id and the old id is nowhere
