A note on the pre-pass capture, so a later reader can reproduce this: the baseline file was written with the
subject's exit status appended as a trailing `RUN_EXIT=0` line, which is *not* part of the run's stdout. The
comparison above drops that one line (`head -n -1`) and then the two streams are byte-identical; with the line
kept, the diff is exactly that one added line. Nothing else differs, and the digest above is over the run's own
532 lines.

**Why byte-identity is the right evidence here.** The pass's subject is *who owns a cell's material*: the plan
reading and the mesh sweep now ask the world's own cells instead of deriving the same material a second time
from a per-column class plane. Two derivations that agree produce the same picture, so a **changed** frame
would have meant the pass changed behaviour rather than ownership — the opposite of what it claims. The moving
number this pass owes is not in the run at all: it is the one-cell differential in
`cell-material-gate-2026-10-14f.txt`, where a world is deliberately made to differ from another in exactly one
cell and the frame's digest moves with it. The run's own frame is the *unchanged* case, and it is unchanged
byte for byte.
