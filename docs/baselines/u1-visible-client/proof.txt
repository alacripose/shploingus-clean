#
# The case logs are **not** kept beside this file: they carry each run's own test-thread PIDs and cargo
# timings, so they are the one artifact of a pass that cannot be reproduced byte-for-byte (§33 recorded that
# trap against §32's nine logs). This file is the harness's own output, and its `bit:` lines quote the PID of
# the thread that bit — which is why **its own digest changes when it is re-run**. The digest in `digests.txt`
# is of the bytes on disk from this run. Each case is still re-runnable by hand: the subject string, the file
# and the selector are all in `run-guards.sh`.
#
# The last block is the check this pass added after §36's own near-miss, and it is worth the words. `cargo
# test` builds the **binary** as well as the test harnesses, so a case that runs while a source is perturbed
# leaves a perturbed binary at `target/debug/shploingus-clean-room` — and a later `window` run of that binary
# reports the perturbation, not the world. That is exactly how a guard case was first read as a rendering
# defect: the read-back "disagreed at 0 of 66 355 200 pixel(s)" and, at (0, 0), the two buffers held **equal**
# bytes ([100, 88, 71, 255] against [100, 88, 71, 0]) because case 12's `if false && …` had short-circuited
# the comparison to `false`. A rebuild from the restored sources made every subsequent run agree on every
# pixel again, and the threshold that was being hunted for did not exist. Every case now rebuilds, and the run
# ends by running that rebuilt binary and comparing its own stdout and stderr against this baseline's frozen
# capture — a tree that came back byte-exact and a build that did not would pass every other check here and
# still be the wrong program.
