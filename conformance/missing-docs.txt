# What the compiler says about documentation: one `crate<TAB>missing<TAB>pin` line per crate.
#
# **This is the `documented` axis's reading, and it is a measurement rather than a claim.** `missing`
# is how many public items the compiler reports without a doc comment, by the `missing_docs` lint
# every crate root enables (`#![warn(missing_docs)]`). `pin` is the digest of the bytes the count was
# taken over: `sha256:` over the crate's covered files — its `src/`, its `tests/`, its `build.rs`, its
# `Cargo.toml` — each contributing its relative path and its bytes, sorted by path, under the domain
# tag `shploingus/missing-docs` (`census::missing_docs_pin`, `census::MISSING_DOCS_DOMAIN`).
#
# The axis reads this file: a crate declaring 0 **with a matching pin** is `active`; a crate declaring
# more is `inactive` with the number, reported every build; a crate whose pin no longer matches its
# files is **`stale`**, which is its own state; and a crate with **no line here** is `refused`,
# because a header saying a crate documents itself is a claim, and the axis asks the compiler instead.
# A line with no pin is refused too: it is a count about an unknown tree, and there would be nothing
# in this project to compare it against.
#
# **Why the pin, and what it changes.** `cargo check` cannot run from inside the gate's own build
# script — it would recurse into the build that is running — so this count is a snapshot a person
# takes. Hashing needs no compiler at all, so the gate re-takes the pin on every build, over the same
# bytes it already reads for the prose measure, and renders a disagreement as `stale` instead of
# printing the number as this build's answer. Without the pin the axis could only repeat whatever it
# was last handed: **the count was always true of a tree, and never necessarily this one.** A stale
# reading is reported — `crate-gap ... state=stale` in the gate's census section and
# `conformance-stale` in its conformance section — and **does not fail the build**, because the
# repair is to re-run the recipe below, which is a command and not an edit; a fatal state here would
# refuse every build until somebody ran a compiler by hand, which is how a gate is routed around.
#
# **How to re-measure — both commands, in this order, after your last edit to a crate.**
#
#     touch crates/*/src/lib.rs crates/*/src/main.rs
#     CARGO_INCREMENTAL=0 cargo check --offline -j 2 --workspace 2>&1 | awk '/^ +(Checking|Compiling) [a-z]/ { seen[$2] = 1 } /warning: missing documentation/ { want = 1; next } want && /--> crates/ { p = $2; sub(/^crates/, "", p); p = substr(p, 2); cut = index(p, "\\"); if (cut > 0) p = substr(p, 1, cut - 1); n[p]++; want = 0 } END { for (c in seen) printf "%s\t%d\n", c, n[c] + 0 }' | grep -E '^(voxel|shploingus)' | sort
#     cargo test -p voxel-package --lib --offline census::tests::the_missing_docs_pins_print_so_the_reading_can_be_re_pinned -- --nocapture
#
# The first prints `crate<TAB>count` and the second prints `crate<TAB>sha256:…`; a row here is the two
# pasted together. **A pin pasted without a fresh count is the one failure this file cannot detect by
# itself** — the pin would match while the number stayed old, so the pin would be evidence for a
# reading nobody re-took. Both commands are in this header for that reason, and neither is optional.
#
# **Neither step of the compiler half is decoration, and both were measured.** The `touch` is not
# optional: cargo replays cached diagnostics for a crate it did not re-check, so without it a crate's
# warnings are simply absent from the output and the reading would credit it with **zero**. Run it and
# the instrument names every crate the run checked — including `Compiling`, not only `Checking`,
# because a crate whose build script or binary target has work to do is compiled rather than merely
# checked, and the first version of this recipe missed exactly those two crates (`voxel-model` 907
# items, `shploingus`) until that was fixed. `CARGO_INCREMENTAL=0` is here because this machine's
# volume runs near full and the gate's own size guard prunes the incremental cache, which makes rustc
# fail to write its dep-graph mid-run (`failed to move dependency graph … os error 3`, exit 101); with
# incremental off the same command exits 0. Both facts are from runs, not from reading about them.
#
# **A crate the run did not check is not a crate with zero**, which is why the rows below are exactly
# the sixteen the last run named: a crate whose line is missing leaves this file without that line
# rather than with a zero, and the axis then refuses it. That failure direction is deliberate — an
# inaccurate zero would be a credential nobody earned.
#
# **What this file still cannot do.** The pin says whether the bytes have moved; it does not say the
# count is *right*, and it cannot catch a count re-pasted unchanged beside a fresh pin. It also covers
# only each crate's covered files — the same universe the prose measure uses, which is what this
# project is written in — so a generated file under `target/` is outside it. Stated here rather than
# discovered later; a malformed line, an unknown crate name, a missing or unparseable pin, or a
# duplicate is a refusal of the whole census.
#
# Re-read 2026-10-10, pins added the same day by the recipe above: **2285 public items across sixteen
# crates carry no doc comment**; three crates are at zero, and the largest single reading is
# `voxel-model` at 907. The counts did not move when the pins were added, and the pins are the state
# of the bytes that produced them.
