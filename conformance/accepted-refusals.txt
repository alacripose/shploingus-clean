# The refusals this record admits, by name — `shploingus.recipe`-style `crate/axis` keys.
#
# **What acceptance means here, and what it does not.**
# An entry on this list does not delete the refusal, fix it, or silence it: the gate still measures
# it, still counts it, and still prints it as `conformance-accepted-by-name` in every build report.
# It only stops the refusal from *failing the build*. Accepted is reported, never hidden.
#
# **An absent list accepts nothing.** Deleting this file makes the build door refuse again — that is
# the door working, not the door breaking.
#
# **No entry is declared, and that is a measurement rather than an omission.** Every key this file
# carried from 2026-10-09 was on the `documented` axis — *this crate carries 19–50% comment and no
# `docs/` heading begins with its name* — and each one named owed work: sixteen sections of real
# documentation, one per crate. That documentation landed on **2026-10-10**, and it landed where the
# user's ruling says it belongs: in each crate's own **rustdoc**, the `//!` and `///` doc comments the
# compiler carries, which `cargo doc` renders as the crate's page and a hover shows on the item. The
# axis does not take that on a header's word: `census::Axis::Documented` reads the compiler's own
# `missing_docs` count (`conformance/missing-docs.txt`, per public item) and names the number in its
# reason — three crates at 0, thirteen carrying debt that is now **reported** rather than accepted. So
# the sixteen keys were deleted,
# and the honest reading of a receipt is no longer *documentation: declared debt* but *documentation:
# lives in the crate it describes*, with the plain-comment share beside it held by the ratchet in
# `conformance/prose-frame.txt` (which measures rustdoc apart from commentary — see its header).
#
# **The sixteen stale keys were a hole, not a formality.** Once the sections landed each key
# answered no refusal, and a key that answers no refusal is not an empty line: it is a **standing
# permission**, and the refusal it names comes straight back if that axis regresses — printing
# nothing while it waits, because `accepted` is computed by asking which refusals the keys match, a
# question that never looks at the keys nothing matched. The gate now computes the other direction
# too and **refuses** a declared key no refusal answers (`conformance-stale-acceptance`, printed by
# key, because the repair is to delete the line). That is this file's own doctrine applied to
# itself: a list that names work it does not have is the same failure as a list that reads silence
# as permission.
#
# **What the axis can still refuse.** A crate the reading does not name — a new member of the
# workspace, or a line dropped from `missing-docs.txt` — becomes `refused` on `documented` until the
# recipe is run again, because *a crate nobody counted is not a documented one*. That is the refusal a
# list should never pre-accept, and nothing here does. **And a crate whose reading has drifted** —
# the pin beside its count no longer matching its files — becomes `stale`, which is its own state and
# not a refusal: the repair is re-running the recipe, so it is reported (`conformance-stale`) and
# deliberately does not close the door. Neither state is reachable from this list, and neither should
# be: this file admits *measurements a reader has decided to tolerate*, not readings that are about
# another tree.
#
# Declared 2026-10-09 with the door's wiring (PATCH-022's *the build door is still not fatal*);
# emptied 2026-10-10, when the retrofit it was holding open landed.

# ---- the one accepted runtime refusal, declared rather than keyed ----
#
# `cell-declaration/old-version` — a display package whose `package.cells` header is
# `shploingus.cells/0` is refused by `voxel_client::shell::cells::declare` with the file and the line
# (`…/old-cell-declaration/package.cells:1`), the burden `shploingus.recipe/3` already carries for an
# old recipe header. The refusal is **accepted by name**: it is the declared mechanism by which the
# old cell drawing stays versioned (`cells 0`, `CellVersion::Elements`) instead of being deleted, and
# the shell keeps drawing the version in force.
#
# **The declaration is read where the package is mounted** (`Mount::load_package`), not once at boot:
# the same refusal therefore holds for a display package that arrives while the shell runs, and it is
# read before the arrangement is adopted — so a refused arrival changes neither the version in force
# nor the windows, the composed frame or the raster runs already on screen.
#
# **It is not a key on this list, and that is deliberate.** A key here is a `crate/axis` conformance
# cell. This refusal is a runtime declaration and no conformance cell answers it, so a key would fail
# the gate as `conformance-stale-acceptance` — a standing permission for a refusal that cannot happen,
# which this file's own header calls a hole. The acceptance is therefore declared in the file the
# gate reads and names, and the refusal is held by
# `crates/voxel-client/tests/cell_version_refusal.rs` on the real mount and frame path — the boot
# package's declared drawing, and a package copied in after boot that is refused while the screen
# stays. **The gate's `conformance-accepted` count remains 0**, and this file says so plainly: the
# commentary is not a key, and a key it cannot answer would be a standing permission for a refusal
# no cell measures. That is the whole of what this record can carry, and it is stated rather than
# implied.
